NLU & LLM Choices

Three LLM jobs with different quality bars and cost profiles. Claude for live NLU, open-source for batch fee extraction, swappable behind a single interface.

The NLU layer (Claude tool-use)

One model call per user message. The model has tools, not freeform output:

Disambiguation flow

If location or date resolution is ambiguous (multiple plausible cities, vague "next weekend"), the model calls needs_clarification instead of submit_search. The API returns the question to the client; the client posts the answer back to POST /clarify and the model continues. Avoids guessing wrong silently.

Prompt caching

The system prompt + airport reference data is shared across calls. Anthropic prompt caching cuts input cost ~90% on cached portions — significant for a stable, large context.

Where the real gap shows up

Try this prompt on each:

"Fly from somewhere near Munich to Crete next month, prefer morning departures, willing to take a train up to 4 hours to get to a cheaper airport, returning to anywhere in southern Germany."

The gap shows in three places:

  • Geographic reasoning: "near Munich" → which airports? "southern Germany" → MUC, STR, NUE, FMM, MEM? OSS models often miss secondary airports.
  • Constraint juggling: 4 simultaneous constraints (origin region, dest, time, transit budget). OSS more often drops one silently.
  • Tool-use chaining: resolve_location → resolve_dates → submit_search. OSS more likely to skip a step or hallucinate arguments.

You can close this with prompting + constrained decoding + evals, but it's real work. Budget 2–4 weeks of eval and prompt iteration to match Claude on this task, plus a regression harness to keep it there.

Cost at v1 scale

At ~1k searches/day, ~1.5k LLM calls/day, ~500k tokens/day:

SetupNLU cost / month
Claude Haiku 4.5~$15
Claude Sonnet 4.6~$60
Llama 3.3 70B (Together)~$13
DeepSeek V3~$8
Self-hosted L3.3 70B on rented H100~$1,400 (idle cost dominates)

At v1 volume, you save $5–10/month by going OSS for NLU. Not worth the eval engineering unless you have other reasons (data residency, offline use, no-vendor-lock-in principle). The math flips around ~100k searches/day: OSS hosted inference saves real money and self-hosting starts to make sense.

The hybrid recommendation

  1. NLU → Claude Haiku 4.5 with prompt caching on the system prompt + airport reference data. Cheap, best-in-class disambiguation, ship faster. Revisit when volume justifies the swap.
  2. Fee extraction worker → Llama 3.3 70B via Together or DeepSeek V3. Batch, offline, easy schema, low risk. Genuine cost win because pages are long (~30k tokens each).
  3. Result summarization → whatever you've already integrated. Even an 8B model works. Easiest to keep on the same provider as fee extraction.
  4. Wrap all three in an LLMProvider — swapping is a config change.

The LLMProvider interface

class LLMProvider(Protocol):
    name: str
    supports_cached_prompt: bool
    supports_json_schema: bool
    supports_tool_use: bool

    async def complete(
        self,
        messages: list[Message],
        *,
        cache_breakpoints: list[int] | None = None,
        max_tokens: int = 1024,
    ) -> Response: ...

    async def call_tools(
        self,
        messages: list[Message],
        tools: list[ToolSpec],
        *,
        force_tool: str | None = None,
    ) -> ToolCalls: ...

    async def structured(
        self,
        messages: list[Message],
        schema: JsonSchema,
    ) -> dict: ...

Eval harness (mandatory if going OSS for NLU)

You can't quietly swap LLMs without a regression harness. Build one with the project; you'll use it forever.

  • ~50–100 hand-graded NLU queries covering: open-jaw, fuzzy dates, ambiguous cities, multi-constraint queries, error cases.
  • Per-query graders: structural (did it produce a valid SearchRequest?), semantic (does the request match what a human would have asked?), behavior (did it ask for clarification when it should have?).
  • Replay test: run the harness on every prompt change. Fail CI if accuracy drops >3% on any category.
  • Fallback escape hatch: if the configured provider returns low confidence (or a malformed tool call), retry with Claude. Users get correct answers while you tune.
Practical note The eval harness pays for itself on the second LLM swap regardless of which providers you choose. Even staying on Claude, you'll want it for prompt regressions and model version bumps.

Privacy / data-residency considerations

User queries can contain personal travel details. If that matters:

  • Anthropic offers AWS Bedrock / GCP Vertex hosting with regional data residency.
  • OSS via Together/Fireworks has US-only inference by default; EU options exist.
  • Self-hosted Llama on your own infra is the only path to fully in-VPC inference. ~$1,400/month minimum.
