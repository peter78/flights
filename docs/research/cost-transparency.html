Cost Transparency

Surface the total cost of a trip up front — base fare plus bag fees, seat selection, parking, and ground tickets — so the user knows what's included before they click.

The problem

A $284 base fare on a basic-economy ticket can become a $370 trip once a checked bag and seat selection are added. Different airlines bundle differently: Delta Main includes a carry-on; Spirit Bare Fare doesn't. Most search tools quote the lowest unbundled fare and leave the user to discover the truth at checkout.

The goal: build a knowledge base of airline ancillary fees, join it to each search result against the user's stated preferences, and rank on the resulting total.

The fee knowledge base

Schema

airline_fee_profile (
    id              bigserial primary key,
    airline_code    char(2) not null,
    fare_brand      text not null,           -- "Basic Economy", "Main Cabin", ...
    region          text not null,           -- "NA", "EU", "domestic-US", etc.
    currency        char(3) not null,

    carry_on_included         bool,
    personal_item_included    bool default true,
    checked_bag_1_price       numeric(8,2),
    checked_bag_2_price       numeric(8,2),
    seat_selection_price_min  numeric(8,2),
    seat_selection_price_max  numeric(8,2),
    change_fee                numeric(8,2),
    cancel_refund_percent     smallint,
    flight_changes_allowed    bool,

    source_url                text not null,
    extracted_at              timestamptz not null,
    extracted_by              text,           -- model id
    extractor_confidence      numeric(3,2),   -- 0.0–1.0
    reviewed_at               timestamptz,
    notes                     text,

    unique (airline_code, fare_brand, region)
)

Seed coverage

~20 airlines covers the long tail of typical demand. Initial seed by hand or via a one-shot extraction run; ongoing refresh by the weekly worker (below).

The fee-extraction worker

Weekly cron, OSS LLM (Llama 3.3 70B or DeepSeek V3 — see NLU & LLMs).

  1. For each airline, fetch the curated fees-page URL (the airline's own published page; not their booking flow — that's a different legal posture).
  2. Hand the HTML plus the target JSON schema to the model with grammar-constrained decoding. Long context helps; fee pages run ~30k tokens.
  3. Parse the structured response. Per-fare-brand rows out.
  4. Diff vs prior week. Flag rows with >20% price changes or new/removed fare brands for manual review.
  5. Write to airline_fee_profile with the new extracted_at. Keep history (versioning via insert, not update).
Why offline Batch + reviewable + low quality bar — the perfect OSS-LLM job. Pages don't change between runs much; one bad extraction has at most a week's blast radius and is correctable by humans before publish.

Per-result enrichment

The orchestrator joins each itinerary against the fee KB and the user's PassengerPrefs:

def enrich_with_costs(itin: Itinerary, prefs: PassengerPrefs) -> CostBreakdown:
    breakdown = CostBreakdown(base=itin.base_price)

    for leg in itin.flight_legs:
        profile = fee_kb.lookup(
            airline = leg.carrier,
            fare_brand = leg.fare_brand or _assume_cheapest_brand(leg.carrier),
            region = _region_of(leg),
        )

        if prefs.checked_bags >= 1 and not profile.checked_bag_1_price == 0:
            breakdown.add("Checked bag (×1)", profile.checked_bag_1_price)
        if prefs.checked_bags >= 2:
            breakdown.add("Checked bag (×2)", profile.checked_bag_2_price)
        if prefs.seat_selection:
            breakdown.add_range(
                "Seat selection",
                profile.seat_selection_price_min,
                profile.seat_selection_price_max,
            )

    return breakdown

The fare-brand gap

Honesty fast-flights doesn't return fare brand. v1 has to assume the cheapest available brand per airline (usually basic economy) and label totals as "estimated".

When a provider supplies fare brand (Duffel, Amadeus), the estimate becomes precise automatically because:

  • The lookup uses the actual brand (itin.fare_brand), not the assumed-cheapest one.
  • Provider-supplied ancillaries (if available) override the KB entirely.
  • The "Estimate — basic economy assumed" label disappears.

Same code path; the difference is just which FlightProvider served the result. This is the payoff for putting cost behind a provider-aware abstraction.

Currency and tax visibility

Three things to get right:

  • Always show prices in the user's selected currency, with an FX rate disclosure when conversion happens.
  • Some rail/bus operators in the EU display pre-tax prices. Normalize to tax-inclusive at the cost layer; mark which legs include tax in the breakdown.
  • US airport parking has resort fees / facility fees not shown in the headline price; the parking source has to provide all-in totals.

Protected intermodal detection

When a journey involves a rail leg into an airport, check the protected_intermodal table:

protected_intermodal:
  - carrier: LH   rail_partner: DB   stations: [FRA, STR, MUC, ...]
    program: "Lufthansa Express Rail"
    deep_link_template: "https://www.lufthansa.com/.../rail?..."

  - carrier: AF   rail_partner: SNCF stations: [CDG, ...]
    program: "TGVAir"
    deep_link_template: "https://www.airfrance.fr/.../tgvair?..."

  - carrier: KLM  rail_partner: NS   stations: [AMS, ...]
    program: "KLM & NS"

  - carrier: BA   rail_partner: NR   stations: [LHR, ...]
    program: "Rail&Fly"

When the rail leg's destination station and the flight leg's carrier match an entry, the Journey is marked protected: true. The UI surfaces this prominently because it changes the user's risk profile (carrier guarantees the connection; missed-train rebooking is the airline's problem, not the user's).

UX cue Protected journeys are worth a visual badge and a single combined deep-link to the airline's bookable intermodal flow, rather than two separate booking links (rail + flight).

Cost-aware ranking

Once each Journey has a CostBreakdown, the ranker can score on total — not just headline fare:

score = w_price * z(total_cost)
      + w_time  * z(total_duration)
      + w_stops * stops_count
      + w_dep   * penalty(dep_time, prefs.preferred_departure_window)
      + w_risk  * (0 if protected else self_transfer_risk_score)

Filters apply before scoring: max stops, dep/arr time windows, max layover length, airlines/alliances allow/deny, max ground portion, carbon ceiling.

What's deferred

  • Per-route fare rules: some routes have bag-included promos that override the brand profile. Defer until you have Duffel/Amadeus.
  • Loyalty-program priced ancillaries: elite-status free bags etc. Defer.
  • Credit-card baggage perks: "United Explorer card waives first bag." Useful but operationally messy; defer to a later phase with user-input preferences.
